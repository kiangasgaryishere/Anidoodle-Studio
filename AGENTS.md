# Permanent Anidoodle studio instructions

- Use the existing checkout. Cloud tasks already run in isolation; do not create a worktree unless the user requests one.
- Read README.md, docs/usage.md, engine/UPSTREAM.md, and `engine/anidoodle/SKILL.md` plus the references relevant to the requested medium before creative work. Follow the user's explicit brief and authorization; ask only for decisions needed to proceed. Never download sound packs, synthesize paid narration, or compose an unrequested soundtrack.
- Keep one shared Anidoodle installation. Prefer its actual Gfx primitives, Film contract, hosts, overlay and render tools; do not replace them with fabricated image/video outputs or a parallel renderer.
- Create every new request under a fresh `projects/<slug>/` using `node scripts/studio.mjs new <slug> --duration <seconds> --size <W>x<H> --fps <fps>`. Never run npm install per project. Reuse engine dependencies. If missing, run `bash scripts/setup.sh` from the studio root.
- Never change an existing project without explicit user authorization. The `new` command must refuse an existing directory. Give each project its own brief, source, configuration, assets and outputs. Store shared reusable assets under assets/ with source/license information.
- Record style, subject, dimensions, duration, FPS, sound, references and defaults in brief.md before drawing. Use frame-driven pure functions and seeded randomness; preserve scale correctness. No wall clock, Math.random or ctx.filter in drawing code.
- Use `scripts/studio.mjs` for still/render/verify/gate/html so pinned Playwright, browser discovery and cloud page loading are applied. Direct upstream commands and generated npm scripts do not apply the cloud adapter. The adapter injects self-contained HTML into a blank page; no external resources are exempted from offline checks.
- Render one preview and inspect it; render representative middle/end frames and a 2x frame when appropriate. Validate exact exported files, not merely process exit or file existence. Use ffprobe/FFmpeg and upstream verify-export. Record passed, failed, skipped and unrun checks distinctly.
- Upstream gate's playwright module lacks probe(); use `gate --adapter html-player`. The slow ambient sample currently fails its strict motion-area threshold; report this honestly, never suppress assertions or change a film's kind to evade it.
- Keep generated large media, node_modules, browser caches, dist and temporary artifacts out of Git. Preserve a compact validation report with command evidence. Never claim animation, audio, 3D or optional backends work unless tested.
- Treat the vendored engine as upstream source: keep its license/provenance, prefer wrapper fixes, and upgrade deliberately in a separate task with regressions checked. Do not re-copy the engine into each project.
- For permanent cloud settings use `bash /workspace/Anidoodle-Studio/scripts/setup.sh` as install script. No persistent server is required; every render starts and closes its own browser.
